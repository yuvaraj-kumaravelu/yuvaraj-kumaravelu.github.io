Real-time streaming Voice AI Fully automated

Custom Nova Sonic AI Voice Agent

A custom real-time audio-streaming architecture, built to get past the latency and flexibility limits of the managed Nova Sonic integration.

  • Fully automated, with no human agent on the call: a Puppeteer headless browser on ECS Fargate logs in to the CCP and answers every call itself. CCP logins are loaded from Amazon RDS, so adding a login adds capacity, up to 5 concurrent calls.
  • A Python FastAPI backend captures the caller's audio from the CCP WebRTC stream, resamples it and streams it with the system prompt to Amazon Bedrock Nova Sonic; the spoken reply is resampled and played back into the live call.
  • Runs inside a VPC: ECS Fargate tasks and RDS in a private subnet, an ALB and NAT Gateway in the public subnet, credentials in Secrets Manager, and Docker images in Amazon ECR.
2-2.5sec
End-to-end response latency, faster than the managed integration's 3.4-4 s

Concurrent AI calls with no human agent, scaling with the CCP logins in RDS
03
Healthcare Voice AI HIPAA-aware

AI Healthcare Receptionist Agent

An AI receptionist for clinics: a Nova Sonic agent in Amazon Connect answers patient calls, handles routine requests itself and hands health questions to a nurse, so the front desk no longer spends time on simple calls.

  • Asks for consent to use the caller's data first (no consent goes to the front desk), then books appointments with any doctor or a specific one, reschedules, cancels and checks insurance coverage through AgentCore Gateway → API Gateway → Lambda tools that call the clinic's own endpoint.
  • Gives no medical advice: symptoms and health questions go to a nurse. Callers who ask for the front desk are routed there during business hours; outside hours they are asked to call back during business hours.
  • A staff portal on Amazon S3 with role-based logins: the front desk and nurses take calls in an embedded CCP with a live transcript (from CloudWatch bot logs) and the earlier AI conversation; admins see AI-handled vs human-handled calls.
  • PHI and HIPAA details are redacted in live transcripts and before records are stored in DynamoDB.

04
QA automation Voice AI Azure DevOps Fully automated

AI-to-AI Calling: Automated QA Voice Testing Agent

An automated QA platform where an AI voice agent tests another AI voice agent through real phone calls, replacing manual test calls.

  • QA writes the test scripts directly in YAML: one file per call path (what the agent says, what the caller says, the expected reply), plus a config.yaml with the project name, target phone number, concurrency and description.
  • Azure DevOps flow: feature branch, QA lead review, a PR to dev with automated DevSecOps checks (structure and data, such as 10-digit phone numbers), then main, whose pipeline sends the scripts to a Python FastAPI backend on ECS Fargate that stores them in RDS with a UUID each.
  • The backend starts outbound calls with StartOutboundVoiceContact through an Amazon Connect outbound campaign; a Nova Sonic QA agent in Connect plays the caller using the test script passed as session attributes.
  • Nova Sonic's speech-to-text gives a turn-by-turn transcript; Claude Sonnet 5.5 on Amazon Bedrock grades it against the YAML script and returns a structured report, stored in RDS and shown in an Azure DevOps dashboard.
4-5hrs
QA testing time, down from 2-3 days
5/task
Calls per Fargate task; CloudWatch adds tasks to match the target's call capacity
